# 公文函的 8-bit 聲音

這篇說明 `alivelog-room/gongwen/index.html` 怎麼加上音效和背景音樂。課程文字、題目、答案都沒有改，只加了聲音，以及右上角兩顆開關。

## 為什麼不用音檔

這一頁本來就是單一 HTML，不載入任何外部資源，進度只放在同學自己的瀏覽器裡。音效如果改放 mp3，就要多檔案，也會碰到素材授權。

所以全部用瀏覽器內建的 Web Audio API 當場算出聲音：方波（做成紅白機那種細一點的脈衝波）、三角波、還有一小段白噪音。沒有音檔，也沒有第三方套件。音量刻意壓低，並加了一層低通濾波，聽起來像紅白機，但不會刺耳。

## 兩顆開關

固定在視窗右上角：

- **🔊 音效**：預設開。
- **🎵 音樂**：預設關。

狀態分別記在 `localStorage` 的 `gongwen.sfx`、`gongwen.bgm`（`1` 開、`0` 關），跟課程進度的 `gongwen.v2` 分開，重新整理還在。

瀏覽器規定，網頁不能自己出聲，要等使用者先點一下。所以 `AudioContext` 會等到第一次點擊或按鍵才建立，並立刻 `resume`。音樂預設關掉，一定要自己按「音樂」才會開始；若上次已經打開並記住了，下一次只要再點頁面上任何地方，就會接著播。

兩顆按鈕都有 `aria-label`（「音效」「音樂」）和 `aria-pressed`。關掉時圖示會變淡，並加一條斜線。

窄螢幕（約 960px 以下）標題列和課程頂部會多留右側空位，避免蓋到「老師 Wen」和「全部打開」。390px 寬時按鈕只留圖示（文字仍在給讀屏軟體），點擊範圍維持 44px。寬螢幕時按鈕落在內容欄外面的右上角，不壓到內文。

切到別的分頁（`visibilitychange`）時，背景音樂會暫停，回到這一頁再接著排程，不會在背景猛播。

## 音效對上哪些動作

| 聲音 | 聽起來 | 什麼時候 |
| --- | --- | --- |
| 答對 `ok` | 上行三音的短叮（E–G–C） | 選擇題答對、抓錯點到真正的錯誤、克漏字或詞庫填對、第 2 關打對 |
| 答錯 `no` | 低沉、很短的一聲 | 選錯、抓錯點到沒問題的句子、填錯、打錯、第 3 關還沒全對、複製時草稿是空的 |
| 短喀 `tap` | 很短的噪音加一點方波 | 選克漏字空格、選詞庫空格、排序放進格子或拿回來、放入骨架或空白格式；音效從關到開時也會喀一聲 |
| 輕刷 `brush` | 噪音由高掃到低 | 翻「簽／函」卡片、點句子展開白話、打開「顯示白話」、打開詳細教材、按「全部打開」、手動打開下一關 |
| 過場 `move` | 較低的三音（C–E–G），比答對沉 | 切換底部分頁、進入主線或支線、按「下一步」、從第 3 關帶去作業 |
| 小勝利 `win` | 約 2 秒的上行旋律 | 小測驗全對、抓錯全找齊、克漏字全部填對、排序排對、第 3 關項目全過、按「我上完這一課了／完成這條支線」、複製草稿成功（這一頁的交作業動作） |

同一種聲音有很短的間隔，避免連點或打字時變成機關槍。答錯大約 0.24 秒內不重複；勝利旋律約 1.5 秒內不疊第二遍。

抓錯的顏色和聲音是反的，這是故意的：公文上的錯字會標紅，但「你找到了」算答對，所以是叮一聲；點到本來就沒錯的句子，畫面是綠的「這裡沒問題」，玩法上算沒抓到，所以是低沉那一聲。

頁面剛載入、還原上次的答案時不會出聲。要等這次操作才播。

## 背景音樂

一段原創的 16 小節、4/4、每分鐘 70 拍，C 大調，偏五聲音階，中間只有幾個經過音。四個聲部：

- 旋律：12.5% 脈衝波，很稀，很多休止
- 和聲：25% 脈衝波，每小節拉長音
- 低音：三角波，第一拍根音、第三拍五度
- 節拍：很輕的高通噪音，落在第二拍和第四拍

和弦走勢是 C–C–Am–Am–F–F–C–G，再 C–Am–F–G–C–Am–F–G。最後一小節停在 G，下一圈回到 C，所以循環接得起來。

播放用排程器：每 25 毫秒看未來約 0.3 秒，把該響的音先掛到音訊時間軸上，而不是用 `setInterval` 直接發聲。這樣比較穩，循環也不會有縫。音量大約是音效的五分之一到十分之一，上課時聽得見，但不會蓋過叮一聲的回饋。
