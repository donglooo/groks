01用 WITH 分段（CTE）

解決什麼一支查詢要做很多步（去重 → 篩選 → 計算 → 彙總）時，全部擠在一層子查詢裡會看不懂。WITH 讓每一步有名字，從上往下讀就是流程。

T-SQL
WITH 篩選 AS (            -- 第 1 步：只留 2024 年起租
    SELECT * FROM 租約
    WHERE 起日 >= '2024-01-01' AND 起日 < '2025-01-01'
), 算日數 AS (            -- 第 2 步：每份契約加一欄日數
    SELECT *, DATEDIFF(day, 起日, 迄日) + 1 AS 日數
    FROM 篩選
)
SELECT 房客, COUNT(*) AS 契約數, SUM(日數) AS 日數合計   -- 最後一步：彙總
FROM 算日數
GROUP BY 房客
ORDER BY 房客;
輸出
房客契約數日數合計
小明2366
小華3458
阿傑115
阿美2195

小華這裡的 458 天是把三份契約直接相加，重疊的天數被算了兩次。第 5 章會修正這個問題。

常見坑
  • 每段用「動詞＋名詞」或「階段名」命名（篩選、去重、算日數），不要叫 A、B、T1。
  • 後面的段只能引用前面的段；同一個 WITH 只寫一次，後面各段用逗號接。
  • WITH 前一句如果沒結束，要補分號：;WITH ...。
  • CTE 不是暫存表：被引用兩次就會算兩次。很重的段要重複用時，考慮 #暫存表（但 view 裡不能用，見第 12 章）。
  • CTE 裡不能放 ORDER BY（除非搭配 TOP）；排序放最外層。

🔑 一段只做一件事、名字說清楚做什麼，之後要查錯就一段一段 SELECT * FROM 那段。

02逐步筆數漏斗

解決什麼每篩一次少了多少筆？用一張「步驟／剩餘筆數／本步排除筆數」表，一眼就能看出哪一步砍最多、有沒有算錯。

T-SQL
WITH 原始 AS (
    SELECT * FROM 租約匯入
), 最新 AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY 契約編號
                                 ORDER BY 匯入時間 DESC, 流水號 DESC) AS RN
    FROM 原始
), 去重   AS (SELECT * FROM 最新   WHERE RN = 1)
,  有房客 AS (SELECT * FROM 去重   WHERE 房客 IS NOT NULL)
,  期間內 AS (SELECT * FROM 有房客 WHERE 起日 >= '2024-01-01' AND 起日 < '2025-01-01')
,  步驟 AS (
    SELECT 1 AS 序, N'原始列' AS 步驟, COUNT(*) AS 剩餘筆數 FROM 原始
    UNION ALL SELECT 2, N'同編號取最新', COUNT(*) FROM 去重
    UNION ALL SELECT 3, N'排除無房客',   COUNT(*) FROM 有房客
    UNION ALL SELECT 4, N'起日在2024年', COUNT(*) FROM 期間內
)
SELECT 序, 步驟, 剩餘筆數,
       LAG(剩餘筆數) OVER (ORDER BY 序) - 剩餘筆數 AS 本步排除筆數
FROM 步驟
ORDER BY 序;
輸出
序步驟剩餘筆數本步排除筆數
1原始列11NULL
2同編號取最新101
3排除無房客91
4起日在2024年81
常見坑
  • 一定要用 UNION ALL：UNION 會去重，兩步剛好同筆數時會少一列。
  • 每一列的第一欄型別要一致；文字加 N''，免得中文變問號。
  • 如果某一步是 JOIN，筆數可能變多（一對多），這時「排除筆數」會是負的。這是警訊，不是排除；要另外標註「這步增加了幾列」。
  • 單位要一致：前面算「契約列」，後面不要突然改算「人數」再相減。

🔑 每多一個篩選段，就在漏斗補一列；數字對得起來，結果才可信。

03每個鍵取最新版本：ROW_NUMBER

解決什麼同一個契約編號被匯入好幾次（改過資料），只想留最新那一筆整列。

輸入：租約匯入（契約 1 有兩版）
流水號契約編號迄日匯入時間
112024-06-302024-01-05 09:00
212024-05-312024-06-10 09:00
322024-12-312024-06-10 09:00
T-SQL
WITH 版本 AS (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY 契約編號          -- 每個編號各自排
                              ORDER BY 匯入時間 DESC,          -- 最新的排第 1
                                       流水號   DESC) AS RN    -- 第二排序鍵：打破平手
    FROM 租約匯入
)
SELECT 契約編號, 迄日, 匯入時間, RN
FROM 版本
WHERE 契約編號 IN (1, 2)
ORDER BY 契約編號, RN;     -- 正式使用時改成 WHERE RN = 1
輸出
契約編號迄日匯入時間RN
12024-05-312024-06-10 09:001
12024-06-302024-01-05 09:002
22024-12-312024-06-10 09:001
常見坑
  • 平手陷阱：兩筆匯入時間一樣時，SQL Server 會隨便挑一筆，而且每次跑可能不同，結果就會飄。一定要補一個唯一欄位（流水號、主鍵）當第二排序鍵。
  • PARTITION BY 裡的欄位如果是 NULL，所有 NULL 會被當成同一組，最後只留一筆。先確認鍵有沒有空值。
  • MAX(匯入時間) 再 JOIN 回原表也能做，但平手時會留下兩筆；ROW_NUMBER 保證只留一筆。
  • 不要對每一欄各自取 MAX：那樣會把不同版本的欄位拼成一列不存在的資料。

🔑 取最新整列 = ROW_NUMBER() OVER (PARTITION BY 鍵 ORDER BY 時間 DESC, 唯一欄 DESC) 加上 WHERE RN = 1。

04閉區間日期：+1 與 −1

解決什麼起日和迄日都算在內（1/1～1/31 是 31 天，不是 30 天）。這叫閉區間。日數要 +1，兩份契約之間的空檔要 −1。

日數 = DATEDIFF(day, 起日, 迄日) + 1
空檔 = DATEDIFF(day, 前一份迄日, 下一份起日) − 1

5/31 結束、6/1 開始：DATEDIFF = 1，空檔 = 0，代表緊接著。1/1 開始、1/1 結束：日數 = 1。

T-SQL
DECLARE @截止 date = '2024-12-31';   -- 統計截止日

SELECT 契約編號, 起日, 迄日,
       IIF(迄日 > @截止, @截止, 迄日) AS 統計迄日,                    -- 截尾
       DATEDIFF(day, 起日, IIF(迄日 > @截止, @截止, 迄日)) + 1 AS 涵蓋日數,
       DATEDIFF(day, LAG(迄日) OVER (PARTITION BY 房客 ORDER BY 起日), 起日) - 1 AS 與上一份空檔
FROM 租約
WHERE 房客 = N'小明'
ORDER BY 起日;
輸出
契約編號起日迄日統計迄日涵蓋日數與上一份空檔
12024-01-012024-05-312024-05-31152NULL
22024-06-012024-12-312024-12-312140
32025-03-012025-08-312024-12-31-5959

第 3 列是錯的：契約在截止日之後才開始，截尾後迄日比起日早，日數變成負數。要先篩 WHERE 起日 <= @截止，再截尾。

常見坑
  • 截尾前先排除「起日晚於截止日」的契約，不然會出現負日數。
  • IIF(a, b, c) 和 CASE WHEN a THEN b ELSE c END 一樣，CASE 可攜性較好。
  • 欄位是 datetime 時，起日 <= '2024-12-31' 會漏掉 12/31 白天的資料。用 起日 < DATEADD(day, 1, @截止)，或先 CONVERT(date, …)。
  • 提前終止：「實際迄日」要先取 COALESCE(提前終止日, 迄日)，再拿去截尾。
  • 截尾後的日數是「截至統計日涵蓋的天數」，不是約定租期，命名時要講清楚。

🔑 兩端都算：日數 +1、空檔 −1；先篩再截尾。

05合併重疊區間（gaps & islands）

解決什麼同一位房客的契約可能重疊或緊接著。要算「實際涵蓋多少天」時，重疊的部分只能算一次，中間的空檔不算。

做法分三步：

  1. 依起日排序，算出前面所有列的最晚迄日（running MAX）。
  2. 如果這列起日和那個最晚迄日之間有空檔（> 0 天），就是新區塊，旗標設 1。
  3. 把旗標累加，得到區塊號；同一區塊用 MIN(起日)、MAX(迄日) 合併。
步驟 1～3
WITH 排序 AS (
    SELECT 房客, 物件, 起日, 迄日,
           MAX(迄日) OVER (PARTITION BY 房客 ORDER BY 起日, 迄日
                           ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS 前面最晚迄日
    FROM 租約
), 旗標 AS (
    SELECT *, CASE WHEN 前面最晚迄日 IS NULL
                     OR DATEDIFF(day, 前面最晚迄日, 起日) - 1 > 0 THEN 1 ELSE 0 END AS 新區塊
    FROM 排序
), 編號 AS (
    SELECT *, SUM(新區塊) OVER (PARTITION BY 房客 ORDER BY 起日, 迄日
                                ROWS UNBOUNDED PRECEDING) AS 區塊號
    FROM 旗標
)
SELECT 房客, 物件, 起日, 迄日, 前面最晚迄日, 新區塊, 區塊號
FROM 編號
WHERE 房客 IN (N'小明', N'小華')
ORDER BY 房客, 起日;
輸出
房客物件起日迄日前面最晚迄日新區塊區塊號
小明A屋2024-01-012024-05-31NULL11
小明A屋2024-06-012024-12-312024-05-3101
小明A屋2025-03-012025-08-312024-12-3112
小華B屋2024-02-012024-07-31NULL11
小華E屋2024-07-012024-09-302024-07-3101
小華B屋2024-08-012025-01-312024-09-3001
步驟 4：合併與累計
-- 接在「編號」後面：合併成區塊，再加總
, 區塊 AS (
    SELECT 房客, 區塊號, MIN(起日) AS 區塊起日, MAX(迄日) AS 區塊迄日
    FROM 編號
    GROUP BY 房客, 區塊號
)
SELECT 房客,
       COUNT(*) AS 區塊數,
       SUM(DATEDIFF(day, 區塊起日, 區塊迄日) + 1) AS 累計日數,          -- 不含空檔、重疊只算一次
       DATEDIFF(day, MIN(區塊起日), MAX(區塊迄日)) + 1 AS 頭尾跨度日數   -- 含空檔，僅供對照
FROM 區塊
GROUP BY 房客
ORDER BY 房客;
輸出

小明2550609

小華的三份契約直接相加是 458 天（第 1 章），合併後是 366 天，因為重疊的天數只算一次。小明的跨度是 609 天，扣掉 59 天空檔後是 550 天。

為什麼不能用 LAG(迄日)？

LAG 只看上一列。如果有一份長約把後面幾份短約整個包住，LAG 會誤判出空檔：

範例資料（虛構）：一份長約包住兩份短約
序起日迄日上一列迄日用LAG算空檔前面最晚迄日用MAX算空檔
12024-01-012024-12-31NULLNULLNULLNULL
22024-03-012024-03-312024-12-31-3062024-12-31-306
32024-05-012024-05-312024-03-3130 ✗2024-12-31-245 ✓
常見坑
  • 框架一定要寫 ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING（不含自己），第一列才會是 NULL。
  • ORDER BY 起日, 迄日：起日相同時補迄日，排序才穩定。
  • 要判斷「相接也合併」用 空檔 > 0 開新區塊；只想合併真正重疊的用 空檔 >= 0。先想清楚定義。
  • 完全相同的列（同起迄）先 DISTINCT，避免重複計算。

🔑 running MAX → 新區塊旗標 → SUM 旗標得區塊號 → GROUP BY 合併。這是處理時間區間最常用的組合。

06用空檔門檻分段

解決什麼允許短暫空檔：同一房客、同一物件，中斷不超過 30 天仍算同一段「連續承租」；超過才切新段。邏輯和第 5 章一樣，只是把「空檔 > 0」換成「空檔 > 門檻」。

T-SQL
DECLARE @門檻 int = 30;

WITH 前一份 AS (
    SELECT 房客, 物件, 起日, 迄日,
           LAG(迄日) OVER (PARTITION BY 房客, 物件 ORDER BY 起日) AS 前迄日
    FROM 租約            -- 正式用時，這裡應先換成第 5 章合併好的區塊
), 旗標 AS (
    SELECT A.*, DATEDIFF(day, A.前迄日, A.起日) - 1 AS 空檔,
           CASE WHEN A.前迄日 IS NULL THEN 1                                   -- 首段
                WHEN DATEDIFF(day, A.前迄日, A.起日) - 1 > @門檻 THEN 1          -- 空檔超過門檻
                WHEN EXISTS (SELECT 1 FROM 租約 B                               -- 空檔內有別人的完整契約
                             WHERE B.物件 = A.物件 AND B.房客 <> A.房客
                               AND B.起日 > A.前迄日 AND B.迄日 < A.起日) THEN 1
                ELSE 0 END AS 新區段
    FROM 前一份 A
), 編號 AS (
    SELECT *, SUM(新區段) OVER (PARTITION BY 房客, 物件 ORDER BY 起日
                                ROWS UNBOUNDED PRECEDING) AS 區段號
    FROM 旗標
)
SELECT 房客, 物件, 起日, 迄日, 空檔, 新區段, 區段號
FROM 編號
WHERE 房客 IN (N'小明', N'阿美')
ORDER BY 房客, 起日;
輸出
房客物件起日迄日空檔新區段區段號
小明A屋2024-01-012024-05-31NULL11
小明A屋2024-06-012024-12-31001
小明A屋2025-03-012025-08-315912
阿美C屋2024-03-012024-03-31NULL11
阿美C屋2024-04-202024-09-301912

阿美的空檔只有 19 天，但這段空檔裡阿傑完整租過 C屋（4/1～4/15），所以還是切成新段。如果拿掉 EXISTS 那一行，阿美就會是同一段。

常見坑
  • 門檻只拿來決定「切不切段」；段內的累計天數仍然不含空檔（加總各區塊日數，不是頭尾相減）。
  • 先合併重疊（第 5 章）再分段，否則重疊的契約會讓 LAG 算出負空檔。
  • 門檻要放在變數或參數 view，不要寫死在好幾個地方。
  • 用語要保守：資料只能證明「有租賃紀錄」，不能證明真的搬進或搬出。

🔑 分段 = 第 5 章的旗標法，換一個門檻條件；想加特殊規則就在 CASE 多加一個 WHEN。

07LAG / LEAD 與 LAST_VALUE 陷阱

解決什麼LAG 取上一列、LEAD 取下一列，用來算「與前一份的空檔」「下一份何時開始」。LAST_VALUE 則有一個很常見的預設框架陷阱。

T-SQL
SELECT 契約編號, 起日,
       LEAD(起日) OVER (PARTITION BY 房客 ORDER BY 起日) AS 下一份起日,
       LAST_VALUE(迄日) OVER (PARTITION BY 房客 ORDER BY 起日) AS 預設框架,
       LAST_VALUE(迄日) OVER (PARTITION BY 房客 ORDER BY 起日
                ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS 指定整段
FROM 租約
WHERE 房客 = N'小明'
ORDER BY 起日;
輸出
契約編號起日下一份起日預設框架指定整段
12024-01-012024-06-012024-05-312025-08-31
22024-06-012025-03-012024-12-312025-08-31
32025-03-01NULL2025-08-312025-08-31

有 ORDER BY 但沒寫框架時，預設是「從第一列到目前這列」，所以 LAST_VALUE 拿到的其實是自己這列，不是整組最後一列。

常見坑
  • 想要整組最後一個值：寫完整框架 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING，或改用 FIRST_VALUE(…) OVER (… ORDER BY 起日 DESC)。
  • 只是要最大值，直接 MAX(迄日) OVER (PARTITION BY 房客) 最省事。
  • LAG/LEAD 第一列、最後一列是 NULL；可用第三個參數給預設值：LAG(迄日, 1, '1900-01-01')。
  • 預設框架是 RANGE，遇到 ORDER BY 值相同的列會一起算進來，結果更難預期；寫 ROWS 比較明確。

🔑 有 ORDER BY 的視窗函數，框架自己寫清楚；LAST_VALUE 不寫框架，幾乎一定是錯的。

08FLOOR vs ROUND：年組分箱

解決什麼把天數分成「未滿1年、1年、2年……8年以上」。關鍵是要無條件捨去，而且要設上限。

T-SQL
SELECT 日數,
       ROUND(日數 / 365.25, 0) AS ROUND_365_25,
       FLOOR(日數 / 365.25)    AS FLOOR_365_25,
       FLOOR(日數 / 365.0)     AS FLOOR_365,
       CASE WHEN 日數 / 365 >= 8 THEN 8                     -- 上限 8：8年以上
            ELSE CONVERT(int, FLOOR(日數 / 365.0)) END AS 年組
FROM (VALUES (200), (364), (365), (548), (729), (730), (2920), (3500)) V(日數);
輸出
日數ROUND_365_25FLOOR_365_25FLOOR_365年組
2001000
3641000
3651011
5482111
7292111
7302122
29208788
350010998
  • ROUND 會四捨五入：200 天被算成「1 年」。用 ROUND 時，「1 年」其實涵蓋約 0.5～1.5 年。
  • FLOOR(÷365.25)：剛好 365 天會落在「未滿1年」，平年的一整年被少算。
  • FLOOR(÷365.0)：365 天 = 1 年。這是「以 365 天換算年」，不是曆法週年。
加上可讀名稱
-- 年組名稱
CASE WHEN 年組 = 0 THEN N'未滿1年'
     WHEN 年組 = 8 THEN N'8年以上'
     ELSE CONVERT(nvarchar(10), 年組) + N'年至未滿' + CONVERT(nvarchar(10), 年組 + 1) + N'年'
END AS 年組名稱
常見坑
  • int / int 在 SQL Server 是整數除法：500 / 365 = 1。要小數就寫 365.0。
  • 日數為非負整數時，日數 / 365 和 FLOOR(日數 / 365.0) 結果一樣。
  • 要真正的週年（考慮閏年，例如 2/29），得用 DATEADD(year, n, 起日) 去比，不能只除天數。
  • 在報表上寫一行註解：「年組以 365 天換算年，非曆法週年」。

🔑 分箱用 FLOOR 不用 ROUND；上限用 CASE；分母寫清楚是 365 還是 365.25。

09CROSS APPLY (VALUES …)：一列展成多列

解決什麼同一份契約要分別用「房客」「物件」「房客＋物件」三種角度分析。與其把同一段查詢 UNION ALL 寫三次（讀三次表），不如讀一次，再把每列展開成三列。

T-SQL
SELECT B.契約編號, V.分析對象, V.主體
FROM 租約 B
CROSS APPLY (VALUES
    (N'房客',       B.房客),
    (N'物件',       B.物件),
    (N'房客＋物件', B.房客 + N'｜' + B.物件)
) V(分析對象, 主體)
WHERE B.契約編號 = 1;
輸出：1 列變 3 列
契約編號分析對象主體
1房客小明
1物件A屋
1房客＋物件小明｜A屋

之後只要 PARTITION BY 分析對象, 主體，第 5 章的合併邏輯寫一次，就能同時算出三種角度。

對照：UNION ALL
-- 等價的 UNION ALL 寫法（讀三次表）
SELECT 契約編號, N'房客' AS 分析對象, 房客 AS 主體 FROM 租約
UNION ALL
SELECT 契約編號, N'物件', 物件 FROM 租約
UNION ALL
SELECT 契約編號, N'房客＋物件', 房客 + N'｜' + 物件 FROM 租約;
常見坑
  • VALUES 每列欄數、型別要一致；空的位置寫 NULL（必要時 CAST(NULL AS nvarchar(10))）。
  • 字串串接遇到 NULL 會整個變 NULL；可以用 CONCAT()，或分成兩個鍵欄位（房客鍵、物件鍵）。
  • CROSS APPLY 右邊沒有列時，左邊那列會消失；要保留就用 OUTER APPLY。
  • 也常拿來做「欄轉列」（unpivot），比 UNPIVOT 好讀，NULL 也保得住。

🔑 同一份資料要用好幾種角度分析：讀一次，用 CROSS APPLY VALUES 展開，再 PARTITION BY 角度。

10EXISTS vs JOIN + MAX

解決什麼要判斷「同物件有沒有別人的契約，且落在某個條件內」。EXISTS 好讀，但它引用的如果是很重的 view，每一列都可能重算一次。改成先 JOIN、再用 MAX(CASE …) 彙總，常常會快很多，而且一次就能算出好幾個旗標。

寫法 A：EXISTS（好讀）
WITH 前一份 AS (
    SELECT 房客, 物件, 起日, 迄日,
           LAG(迄日) OVER (PARTITION BY 房客, 物件 ORDER BY 起日) AS 前迄日
    FROM 租約
)
SELECT A.房客, A.物件, A.前迄日, A.起日,
       CASE WHEN EXISTS (SELECT 1 FROM 租約 B
                         WHERE B.物件 = A.物件 AND B.房客 <> A.房客
                           AND B.起日 > A.前迄日 AND B.迄日 < A.起日)
            THEN 1 ELSE 0 END AS 空檔內有他人
FROM 前一份 A
WHERE A.物件 = N'C屋';
寫法 B：JOIN 一次 + MAX（兩個旗標一起算）
WITH 前一份 AS (
    SELECT 房客, 物件, 起日, 迄日,
           LAG(迄日) OVER (PARTITION BY 房客, 物件 ORDER BY 起日) AS 前迄日
    FROM 租約
)
SELECT A.房客, A.物件, A.前迄日, A.起日,
       MAX(CASE WHEN B.起日 > A.前迄日 AND B.迄日 < A.起日 THEN 1 ELSE 0 END) AS 空檔內有他人,
       MAX(CASE WHEN B.起日 <= A.迄日  AND B.迄日 >= A.起日 THEN 1 ELSE 0 END) AS 有他人重疊
FROM 前一份 A
LEFT JOIN 租約 B ON B.物件 = A.物件 AND B.房客 <> A.房客
WHERE A.物件 = N'C屋'
GROUP BY A.房客, A.物件, A.前迄日, A.起日
ORDER BY A.房客, A.起日;
輸出（C屋）
房客物件前迄日起日空檔內有他人有他人重疊
阿傑C屋NULL2024-04-0100
阿美C屋NULL2024-03-0100
阿美C屋2024-03-312024-04-2010

兩段重疊的判斷式：B.起日 <= A.迄日 AND B.迄日 >= A.起日（閉區間）。這個公式很常用，值得背起來。

常見坑
  • 用 LEFT JOIN：沒有別人的列才不會消失，旗標會是 0。
  • GROUP BY 要包含能唯一識別 A 列的欄位，不然不同列會被併在一起。
  • JOIN 可能一對多，所以一定要先彙總回「每個 A 一列」，再拿去和別的表 JOIN。
  • 資料量小、來源是實體表又有索引時，EXISTS 通常已經夠快。改寫前後都要比對結果是否一致（雙向 EXCEPT）。

🔑 多個「有沒有」的判斷：JOIN 一次、MAX(CASE…) 一次算完，比好幾個 EXISTS 各掃一遍省。

11某一天有效：BETWEEN 起迄

解決什麼「某天當下還有效的契約有幾份？」閉區間的寫法就是 @d BETWEEN 起日 AND 迄日（兩端都算）。

T-SQL
DECLARE @d date = '2024-07-15';

SELECT 契約編號, 房客, 物件, 起日, 迄日
FROM 租約
WHERE @d BETWEEN 起日 AND 迄日     -- 等於 起日 <= @d AND 迄日 >= @d
ORDER BY 契約編號;
輸出
契約編號房客物件起日迄日
2小明A屋2024-06-012024-12-31
4小華B屋2024-02-012024-07-31
7阿美C屋2024-04-202024-09-30
9小華E屋2024-07-012024-09-30
常見坑
  • 用「實際迄日」（有提前終止就用終止日），不要用為了統計而截尾過的迄日。
  • 欄位是 datetime 時，BETWEEN 的上界只到 00:00:00；先 CONVERT(date, …) 再比。
  • BETWEEN a AND b 必須 a ≤ b，寫反了不會報錯，只會查不到資料。
  • 要算「期間內曾經有效」（不是單一天），改用第 10 章的重疊公式。

🔑 單一天有效：@d BETWEEN 起日 AND 實際迄日；先確認日期型別。

12做成 VIEW：參數 view、GO、分層

解決什麼想讓別人（或以後的自己）直接 SELECT * FROM 某view WHERE … 查明細，不用每次跑一大段腳本。

  • view 裡不能用 DECLARE 變數，也不能用 #暫存表。
  • 參數改放一支只有一列的「參數 view」，其他 view 用 CROSS JOIN 帶進來。
  • 每支 CREATE VIEW 必須是批次裡的第一句，用 GO 隔開。
  • 分層：底層算明細，上層再彙總；上層依賴下層，要照順序建立。
T-SQL
CREATE OR ALTER VIEW dbo.vw_練習_參數 AS
SELECT CONVERT(date, '2024-12-31') AS 統計截止日,
       CONVERT(int, 30)            AS 空檔門檻天數
GO
CREATE OR ALTER VIEW dbo.vw_練習_契約 AS
SELECT A.契約編號, A.房客, A.物件, A.起日, A.迄日,
       IIF(A.迄日 > P.統計截止日, P.統計截止日, A.迄日) AS 統計迄日,
       DATEDIFF(day, A.起日, IIF(A.迄日 > P.統計截止日, P.統計截止日, A.迄日)) + 1 AS 涵蓋日數
FROM dbo.租約 A
CROSS JOIN dbo.vw_練習_參數 P
WHERE A.起日 <= P.統計截止日
GO
-- 使用
SELECT * FROM dbo.vw_練習_契約 WHERE 房客 = N'小明' ORDER BY 起日;
輸出
契約編號房客物件起日迄日統計迄日涵蓋日數
1小明A屋2024-01-012024-05-312024-05-31152
2小明A屋2024-06-012024-12-312024-12-31214
常見坑
  • CREATE OR ALTER 要 SQL Server 2016 SP1 以上；更舊的版本先 DROP VIEW，再 CREATE VIEW。
  • view 裡不能放 ORDER BY（除非加 TOP），排序寫在查詢時。
  • view 不會存結果，每次查詢都從頭重算。很慢的話，改成排程把結果寫進實體表。
  • 有視窗函數、CTE、外部聯結的 view 不能做 indexed view。
  • DBeaver 預設把空白行當成語句分隔，view 本體裡別留空行（或改設定）。
  • 建 view 前先確認 schema 和權限；view 裡如果有敏感欄位，查詢權限要收緊。

🔑 變數換成參數 view、暫存表換成分層 view、每支用 GO 隔開，照依賴順序建立。

13DBeaver 小技巧

解決什麼同一份腳本，用不同方式執行，結果差很多。

按鍵做什麼什麼時候用
Ctrl+Enter只執行游標所在（或選取）的那一句測單一段 SELECT
Alt+X執行整份腳本，每句各一個結果分頁有 DECLARE、#暫存表、建 view 時
選取多行 + Ctrl+Enter把選取範圍當一句送出DECLARE 加上要用它的那句一起跑
  • 只顯示 200 列：結果格預設只抓前 200 列，畫面上的列數不等於總數。總數用 COUNT(*) 查，或在結果下方點「取得全部列」。
  • 要完整明細：在結果上按右鍵 →「Export data」（匯出資料）→ CSV／Excel，它會重新執行查詢並匯出全部列。
  • DECLARE 的範圍：變數只在同一批次有效。只用 Ctrl+Enter 跑後面那句，會出現「必須宣告純量變數」。
  • #暫存表：同一個連線（session）內都有效；換個編輯器分頁可能是另一個連線，就看不到了。
常見坑
  • 把 200 列當成全部結果去統計。
  • 匯出前沒確認連線是正式還是測試資料庫。
  • 含個資的明細不要截圖或貼到外面；只看自己需要的那幾筆，用 WHERE 篩。

🔑 建表、建 view、有變數時用 Alt+X；看總數用 COUNT；要完整明細用 Export data。

小練習

用上面的範例資料就能做。先自己寫，再展開答案對照。

練習 1　3/1 起租、3/31 退租是幾天？3/31 退租、4/20 再起租，中間空檔幾天？用 SQL 算出來。

看答案
參考答案
SELECT DATEDIFF(day, '2024-03-01', '2024-03-31') + 1 AS 日數,      -- 31
       DATEDIFF(day, '2024-03-31', '2024-04-20') - 1 AS 空檔;     -- 19

日數 +1（兩端都算），空檔 −1（兩端都不算）。

練習 2　「租約匯入」裡，每個契約編號只留最新一筆，且匯入時間平手時也要穩定。寫出查詢。

看答案
參考答案
WITH V AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY 契約編號
                                 ORDER BY 匯入時間 DESC, 流水號 DESC) AS RN
    FROM 租約匯入
)
SELECT * FROM V WHERE RN = 1;

流水號是唯一欄位，用來打破平手。

練習 3　2024-04-10 當天，C屋有幾份有效契約？是誰的？

看答案
參考答案
DECLARE @d date = '2024-04-10';
SELECT 房客, 起日, 迄日
FROM 租約
WHERE 物件 = N'C屋' AND @d BETWEEN 起日 AND 迄日;
-- 1 份：阿傑（2024-04-01～2024-04-15）

阿美 3/31 已結束、4/20 才再起租，4/10 不算有效。

練習 4　以「物件」為主體（不是房客），算每間屋子的累計出租日數（重疊只算一次、空檔不算）。提示：把第 5 章的 PARTITION BY 房客 換掉。

看答案
參考答案
WITH 排序 AS (
    SELECT 物件, 起日, 迄日,
           MAX(迄日) OVER (PARTITION BY 物件 ORDER BY 起日, 迄日
                           ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS 前面最晚迄日
    FROM 租約
), 旗標 AS (
    SELECT *, CASE WHEN 前面最晚迄日 IS NULL
                     OR DATEDIFF(day, 前面最晚迄日, 起日) - 1 > 0 THEN 1 ELSE 0 END AS 新區塊
    FROM 排序
), 編號 AS (
    SELECT *, SUM(新區塊) OVER (PARTITION BY 物件 ORDER BY 起日, 迄日 ROWS UNBOUNDED PRECEDING) AS 區塊號
    FROM 旗標
), 區塊 AS (
    SELECT 物件, 區塊號, MIN(起日) AS s, MAX(迄日) AS e FROM 編號 GROUP BY 物件, 區塊號
)
SELECT 物件, SUM(DATEDIFF(day, s, e) + 1) AS 累計出租日數
FROM 區塊 GROUP BY 物件 ORDER BY 物件;
-- A屋 550、B屋 366、C屋 210、E屋 92

C屋：3/1～3/31（31）＋ 4/1～4/15（15）＋ 4/20～9/30（164）= 210。3/31 和 4/1 緊接著，所以前兩份會併成同一個區塊。

練習 5　把第 8 章的年組換成「每 2 年一組、上限 6 年以上」（0、2、4、6）。

看答案
參考答案
SELECT 日數,
       CASE WHEN 日數 / 365 >= 6 THEN 6
            ELSE (日數 / 365) / 2 * 2 END AS 年組
FROM (VALUES (364), (730), (1459), (1460), (3000)) V(日數);
-- 0, 2, 2, 4, 6

整數除法本身就是無條件捨去：(年 / 2) * 2 會把年數變成偶數下界。
